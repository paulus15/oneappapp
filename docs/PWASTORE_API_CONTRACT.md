# PWA Store — Contrat d'API

Base : `{APP_URL}/api` (local `https://oneapp.test/api`, production `https://pwastore.online/api`). Format JSON. Authentification : `Authorization: Bearer <jeton Sanctum>`.

Légende statut : **E** existe et testé · **E\*** existe, à corriger · **N** nouveau (lot indiqué).
Auth : `—` public · `U` compte connecté · `D` profil développeur · `A` administrateur (permission indiquée).

## Conventions

- Langue : le front envoie `Accept-Language: fr|en` (choix mémorisé dans le navigateur) ; l'API répond avec `Content-Language`. Le français est la langue source et la valeur par défaut. Messages traduits : manques de soumission et blocages éditeur (`lang/en.json`) ; la traduction des autres messages serveur et des e-mails est en cours (revue de sécurité, H11). Connecté, la langue choisie est aussi enregistrée sur le compte (`PUT /account/locale`).
- Pays : connecté, le pays du profil s’applique ; visiteur, l’en-tête `X-Country: CI` (choix explicite mémorisé dans le navigateur, jamais déduit de l’IP). Sans pays, seules les applications disponibles partout sont listées. Une fiche non proposée dans le pays répond `403` « Cette application n’est pas disponible dans votre pays. ».
- Médias : adresses relatives `/api/media/...` (le front les complète avec l’origine de l’API). Couvertures : `/api/media/covers/{uuid}/{640|1280|1920}.{avif|webp|jpg}`, cache d’un an.
- Erreurs de validation : `422` avec `{ message, errors: { champ: [..] } }`.
- Refus de droit : `403` avec `message` en français, lisible par l'utilisateur.
- Conflit d'état (transition interdite, quota) : `409` avec `message`.
- Trop de requêtes : `429`.
- OTP requis : `202` avec `{ requires_otp: true, challenge_id, purpose, channel, destination, expires_at, retry_after, code_sent, message }`.
- Listes paginées : format Laravel `{ data, current_page, last_page, per_page, total }`.
- Session ouverte : `{ user, access_token, token_type: "Bearer" }`. `user` = `accountPayload` : attributs du compte, `country`, `developer_profile`, `capabilities`, `publication_blockers`.

## 8. Compatibilité

- Les routes existantes gardent leur forme. Les changements de réponse sont additifs (nouveaux champs).
- `applications.status` : pendant la migration, l'API renvoie le nouveau statut et un champ `legacy_status` pour la vitrine Blade, jusqu'à son retrait.
- Toute route modifiée reçoit un test de non-régression avant d'être changée.

| POST    | `/admin/publication-requests/{id}/decide`          | A    | Approuver la demande d’une app suspendue exige `lift_suspension: true` (journalisé) ; la réponse ne dit « en ligne » que si l’app l’est réellement                                                                                                                              |

Champs internes (motif de modération, score de confiance, rapport de contrôle, clé de mesure) : masqués par défaut dans toutes les réponses, révélés au seul développeur propriétaire et aux modérateurs. Les intentions d’installation (`/install-intents/{token}`) ne renvoient que des champs publics.

### Déploiement de l’attribution PWASTORE

Avant le déploiement, terminer les anciens jobs de mesure puis arrêter les workers. Appliquer la migration backend `2026_10_13_120000_attribute_install_signals_to_store` avant de servir le contrôleur mis à jour et de redémarrer les workers. Elle ajoute `store_referred_at`, sans modifier les données historiques. Les nouveaux compteurs excluent les lignes sans cette date. Un nouveau clic valide initialise leurs compteurs attribués ; aucune valeur historique n’est importée. Les extraits HTML déjà collés restent valides. Un ancien script en cache peut encore envoyer des événements, mais le serveur applique le même filtre. Le nouveau script est mis en cache cinq minutes ; une ancienne réponse peut conserver son ancien cache jusqu’à 24 heures.

Validation isolée : `vendor/bin/phpunit tests/Feature/InstallSignalTest.php tests/Feature/BackendHardeningTest.php` (SQLite en mémoire) et `node --test tests/sdk-attribution.test.mjs` dans le backend.

Les correctifs backend préparés dans ce dépôt sont `deploy/patches/pwastore-attribution.patch` (SDK, attribution serveur, traitement en file d’attente, migration et tests) et `deploy/patches/pwastore-mail-icon.patch` (icône commune aux emails de confirmation, de contact et de notification, avec tests de rendu). Les deux correctifs ont été appliqués au backend local le 13 octobre 2026, ainsi que la migration d’attribution sur la base locale. Les 29 tests backend ciblés, 7 tests du SDK et 6 tests de traduction passent. Aucun déploiement en production n’a été effectué. Le signal de redémarrage des workers locaux a échoué car le PHP CLI ne charge pas l’extension Redis ; les workers devront être redémarrés avec un PHP disposant de cette extension.
